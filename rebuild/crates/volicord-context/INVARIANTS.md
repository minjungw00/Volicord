# Canonical Context invariant catalog

This is the internal production contract for `volicord-context`. Product meaning
remains owned by `rebuild/docs/design/`; this catalog maps that meaning to the
current implementation and executable evidence.

The boundaries are deliberately distinct:

- **Transition preconditions** validate one requested command and its expected
  revision, authority, and input basis before changing rows.
- **Full-state invariants** validate the complete resulting Project through
  `canonical_state::validate_payload`; direct writes validate their transaction
  through `canonical_state::validate_project_state` before commit.
- **Local operational invariants** cover operation replay, dependency cleanup,
  managed paths, lineage bookkeeping, and clone bindings. These rows are not
  portable Canonical Context and are enforced by `store`, `portable`, and
  `merge` operations plus SQLite constraints.
- **Portable canonical invariants** apply to the allowlisted complete Project
  payload used by export, `validate_bundle`, import, generated merge targets,
  state replacement, and `ExplicitMerged`.

An anchor names an executable Rust test. “Incomplete” is an explicit coverage
limit, not a passing claim.

## Current coverage boundary

The response-history invariant is production-enforced for direct postconditions,
export, import, generated merge targets, replacement, and explicit merged input.
The maintained V04 mutation matrix recomputes checksum and lineage, crosses
import and `ExplicitMerged`, and proves unchanged canonical read, deterministic
export, lineage, binding, replay state, managed bytes, and reopened state. V04
also maps direct/export/import, forgetting, both merge-forgetting orientations,
replay, and restart metamorphisms. Generated targets and isolated export use
representative states because arbitrary invalid generated state is not an
injectable production surface. Remote authenticity and cryptographic
attestation are not part of this local integrity contract.
