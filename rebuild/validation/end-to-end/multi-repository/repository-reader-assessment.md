# Repository reader assessment procedure

Focused Reader D-34–37 / AC-32–35 support, subordinate to the validation and
qualitative-review owners. This procedure neither generates an answer key nor
adds a scoring platform or qualification gate.

Before inspecting candidate article text, a source-first evaluator reads original
code, readable configuration and tests for the exact complex Rust workspace and
the materially different JavaScript repository. Preserve a timestamped expectation
file with repository revision, file hashes and original line/byte ranges, confidence,
important responsibilities, relations, distinct operations, setup, input/output,
storage and failure boundaries. Record excluded areas and uncertain inferences.
An inventory or a fixed number of files is not a sufficient expectation. Tests
read as source do not establish an executed result. Keep this file private and
out of generation input, Product prose and the first-reading package.

The author investigates the Product's actual preparation and permitted Sources
without that expectation file. Keep every draft, failed admission, first admitted
publication and feedback-guided revision separately. Record current Source scope,
format, expiry, Analysis, Project/Work and realization identities. A new observation
has its own permission, time and identity; it does not renew an old copy. An actual
Workless subject cannot be replaced by an invented Work. Independent name, summary,
article and typed verification publications retain their separate authority.

Give a presentation-first evaluator only the unmodified Product export, optional
desktop/mobile captures, and the answer-free tasks in `package_product_review.py`.
Use a fresh evaluator context with no inherited source-first answers, producer
drafts, preselected claims or previous feedback. Preserve the exact instructions,
allowed inputs, evaluator identity, input hashes, timestamps and original response.
If that separation cannot be demonstrated, mark the reading dependent/not blind.
Agent observations never become actual human acceptance.

For important effect claims, use `effect_review.py freeze --input ORIGINAL.json
--output NEW_BASIS_DIRECTORY` before reading new prose. Each expectation records
conditions, distinct state objects, effects and bounded non-effects, evidence scope,
and exact required implementation/callee/callback ranges. Supply original file hashes
and actual permitted Product Source read receipts; the tool verifies their bytes and
seals a copy. A receiver calling a helper proves neither queue deletion nor request
cancellation. Inspect the helper and any callback that produces the claimed effect.
Missing permitted bodies remain a scoped gap; do not renew or rebind an old Source.

After supported composition, recording and public readback, save the exact public
`QuestionAnswers` object. `effect_review.py prepare --basis BASIS --publication
PUBLIC.json --output NEW_ATTEMPT` seals those inputs and neutral comparison instructions
before the first response. A reviewer then supplies exact unit/UTF-8 claim coordinates,
quotes, supported/contradicted/unestablished verdicts and reasons for every expectation.
`effect_review.py assess --attempt ATTEMPT --response FIRST_RESPONSE.json` preserves
that response before validation. Contradictions, unestablished or missing explanations,
inflated evidence scope and absent effect-producing citations fail the comparison.
A supported verdict is still the reviewer's judgment, never machine-proven entailment.
Self-tests exercise the protocol, not repository semantic quality. Demonstrate actual
semantic rejection against independently inspected originals as separate evidence.

Apply the same expectations to critical shared claims in all applicable languages and
revisions, including headings and synopsis. Earlier English text is no oracle. Changed
Source bytes or scope require a fresh basis and assessment; original attempts remain.
The comparison package contains expectations and therefore is **dependent**, even if
its reviewer is fresh. A presentation-first evaluator must instead receive only the
identified public reading material and neutral tasks described above, with no shared
context, defect descriptions, expected answers, previous findings or feedback.

Only after first reading is sealed should the source-first evaluator compare the
publication against the frozen expectations. Report important missing responsibilities
and causal bridges, unsupported assertions and relevance of each reviewed claim's
actual citation range. Record headings, synopsis and body separately: quiet provenance
does not waive grounding. Hash-valid ranges establish correspondence, not entailment.
Keep a useful but partial article distinct from repository-wide semantic adequacy.
Do not copy missing answers into the producer as an allegedly independent retry.

Use the same frozen expectations for any budget/research alternatives, recording
unavailable alternatives explicitly. Compare missing meaning alongside preparation,
response, retention, retrieval, cold/warm CPU/RSS, HTML and dynamic Source costs.
Neither larger output nor fewer visible actions establishes an improvement.
Source-first, presentation-first, technical, environmental, human and naturalistic
outcomes remain separate, including required positives that are still blocked.

Run the maintained browser drivers on exact current output, measuring real rectangles
after scrolling at 1440/1024/768/390/320 pixels. Include Source open/return, history,
keyboard/focus, script-free fragments, 0/1/many long headings and horizontal overflow.
Report native zoom and assistive use as unobserved unless actually exercised.
Verify the sanitized package independently, including each internal file/fragment
target, containment, membership and hashes. Preserve raw Sources and Runtime stores
only in ignored authorized evidence storage. Invite actual user reading separately.
