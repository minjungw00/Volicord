# `volicord.record_shaping_checkpoint` reference

This document owns the public method that creates or replaces the current
`ShapingCheckpoint` for an `advisor` or `work` Task. It does not finalize
advisor advice, apply an advisor-owned shaping decision, establish a close
basis, advance a Task phase, record a Run, or write Product Repository files.

<a id="surface-stability"></a>
## Surface Stability

The method name, direct request and response schemas, aggregate transaction,
and checkpoint-readiness semantics are `stable`.

The method's entry in the current MCP action-form catalog is state-bound. For
`create_initial`, its caller-visible fixed arguments are Task, the exact
`create_initial` operation, scope revision, and actual nullable baseline. The
adapter injects project and expected state version from the admitted form. It suggests empty source and
evidence refs and leaves only summary, required-nullable implementation
boundary, and typed gaps as required Agent input. For `replace_current` it also
fixes `checkpoint_operation.expected_current_checkpoint_id`, retirement refs,
carry-forward refs, and stale-application refs. Current and predecessor
checkpoint refs remain contextual lineage and are not top-level mutation
arguments. The generic binder requires every fixed path to be present and
deeply equal before Core. MCP admits this method only
when its Agent descriptor is present in the current workflow transition catalog and requires this
method-and-variant form's exact `action_form_ref` before Core invocation.

`checkpoint_operation.operation=create_initial` requires no current checkpoint.
`checkpoint_operation.operation=replace_current` compare-and-swaps the exact
`expected_current_checkpoint_id`. The replacement must provide the complete
exact `retired_non_authorizing_request_refs`,
`carry_forward_application_refs`, and `stale_authority_actions` sets required
by current authority. Missing, extra, duplicate, stale, superseded, foreign,
or decision-kind-conflicting refs reject before mutation.

Every user-owned gap carries exactly one compatible `ShapingUserActionDraft`.
Core creates and links its current `UserActionRequest` in the same transaction.
A non-user-owned gap cannot carry that draft. Reauthorization preserves the
judgment kind and application owner but creates a fresh successor gap and
request identity; it never reuses a stale accepted resolution.

Core derives `readiness`. A checkpoint is `ready` when its baseline and
implementation or advisory boundary are complete, every non-user gap is
closed, and no user-owned gap remains `current`. Accepted decisions remain
`accepted` until their semantic application owner applies them. Recording a
checkpoint never establishes a close basis.

For work Tasks, product, technical, and sensitive shaping decisions are
applied by `volicord.advance_task`; scope decisions are applied by
`volicord.update_scope`. For advisor Tasks, product, technical, and sensitive
decisions are applied only by `volicord.finalize_advice`; advisor scope
decisions remain owned by `volicord.update_scope`.

## Atomic behavior

One committed call validates the exact Task, state version, scope coordinate,
and checkpoint succession; supersedes the predecessor when applicable;
inserts the successor, gaps, UserAction requests, links, carry-forward
lineage, and stale-authority disposition lineage; appends one method event;
stores the exact replay result; and increments `state_version` exactly once.
Failure rolls back the whole aggregate. Exact replay returns the original
result, while a conflicting replay has no effect.

The method never creates a UserAction resolution, decision application, close
basis, Run, Change Unit, write ticket, Product Repository file effect, or Task
phase transition.

## Workflow recovery and presentation

Calling the method outside `advisor|work` plus `work_phase=shaping` returns the
common typed no-effect workflow rejection. A current stale application selects
`shaping_required`, `next_actor=agent`,
a required `volicord.record_shaping_checkpoint` transition, and
`blocking_reason=application_authority_stale`. Rejected, deferred, or expired
authority selects `decision_recovery_required` with the same recovery method.

A committed checkpoint with a current user-owned gap selects
`awaiting_user_action`. Once an advisor checkpoint, its non-write Change Unit,
and all required decisions are ready, workflow selects
`ready_to_finalize_advice` with a required `volicord.finalize_advice` transition.
Work Tasks instead select `ready_for_implementation` and
`volicord.advance_task`.
